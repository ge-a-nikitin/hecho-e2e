# hecho-e2e

E2E-тесты для **HECHO order desk** — доски заказов с ролями заказчика, исполнителя и администратора.
Сам продукт живёт в отдельном репозитории и подключён сюда как система под тестом (SUT) только для
чтения.

Набор гоняет настоящий браузер против настоящего стека (web, API, PostgreSQL, SeaweedFS) и отправляет
результаты кейсов в Qase TestOps.

Основная документация — на английском: [README.md](./README.md),
[docs/conventions.md](./docs/conventions.md), [docs/strategy.md](./docs/strategy.md),
[docs/sut/](./docs/sut/). Этот файл — краткая русская версия.

## Быстрый старт

```bash
pnpm install
pnpm exec playwright install chromium
cp .env.e2e.example .env.e2e       # необязательно: у всех значений есть значения по умолчанию

pnpm e2e                           # при необходимости соберёт и поднимет стек, прогонит оба проекта
```

Первый запуск собирает два docker-образа из SUT, поэтому занимает несколько минут. Дальше стек
переиспользуется.

## Что нужно

- Node.js 22 и pnpm 12 (точная версия зафиксирована в `packageManager`).
- Docker с Compose v2.
- Чекаут SUT в `../order-desk` либо переменная `SUT_DIR`. В CI SUT выкачивается на коммит из
  `sut.lock.json`.

## Полезные команды

| Команда             | Что делает                                                     |
| ------------------- | -------------------------------------------------------------- |
| `pnpm e2e`          | весь набор: setup-проект, затем `chromium` и `pixel-7`           |
| `pnpm e2e:smoke`    | только кейсы `@smoke`                                          |
| `pnpm stack:up`     | собрать и поднять e2e-стек, дождаться health                    |
| `pnpm stack:down`   | остановить стек и удалить тома                                  |
| `pnpm stack:reset`  | очистить базу через `POST /api/devtools/reset`                  |
| `pnpm sut:status`   | какой коммит SUT подключён и актуален ли снимок контекста       |
| `pnpm sut:sync`     | перегенерировать `docs/generated/` из чекаута SUT               |
| `pnpm qase:check`   | офлайн-сверка каталога кейсов и спеков                          |
| `pnpm qase:sync`    | выгрузить каталог в TestOps и обновить `qase/case-ids.ts`       |

## Структура

```
tests/           спеки Playwright: setup и по каталогу на доменную область
support/         env, HTTP-клиент, devtools-клиент, фабрика данных, жизненный цикл стека
qase/            каталог TestOps, резолвер заголовков qc(), сгенерированные id кейсов
docs/sut/        что делает SUT: домен, статусы, маршруты, API, devtools, окружение, особенности
docs/generated/  машинный снимок SUT: test id, маршруты, эндпоинты, enum'ы
scripts/         генератор контекста SUT, обёртка стека, синхронизация и проверка Qase
```

Набор сейчас пуст намеренно: каталог и спеки сброшены, первый кейс начинается с чистой доски.
Состояние и порядок возврата покрытия записаны в `docs/backlog.md`.

## Правила

Как пишется кейс — в [docs/conventions.md](./docs/conventions.md): только `data-testid` в локаторах,
один тест — один кейс Qase, данные через `factory`, проверка видимого результата, без ожиданий по
времени. Там же правило для кейса, который имеет смысл только на одном вьюпорте, и порядок работы с
дефектом: он оформляется в репозитории SUT и помечается `test.fixme` здесь.

## Qase

Кейсы лежат в общем проекте `HECHO` в сюитах `E2E / …`. Локальные прогоны и прогоны в pull request
идут с `QASE_MODE=off` и не требуют токена; публикация результатов — из `main`. Подробности в
[docs/qase.md](./docs/qase.md).
